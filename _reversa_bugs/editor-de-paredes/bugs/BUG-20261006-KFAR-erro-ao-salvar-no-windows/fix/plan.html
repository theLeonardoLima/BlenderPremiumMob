Defeito e causa raiz

No Windows, o OK do editor de paredes (e o construtor) falha: GeoNodeWall.blend failed to open blend file. O .gitignore ignora *.blend; os 107 .blend do pacote caffmob_draw/ nunca foram para o GitHub (só os da cópia antiga na raiz). O titular gera o plugin a partir de um clone: o zip sai com 0 de 107 arquivos. Reproduzido com um clone limpo do master. Evidência: reproduction.md.

Estratégia: correção direta

Versionar os .blend do pacote (exceção só para caffmob_draw/; os .blend de projeto continuam fora do git) e fazer o build.py recusar um pacote sem os arquivos que o código usa, em vez de gerar um plugin quebrado.

Riscos e o que fica de fora

  • Risco baixo: o código do plugin não muda.
  • Fora: o branch padrão do GitHub é o main (antigo, 4b87c21, ainda "blendertomob"); quem clonar sem escolher o branch pega a versão velha. Sugestão: trocar o branch padrão para master nas configurações do GitHub (ação sua) ou alinhar o main.
  • No Windows, depois do push: git pull no master e gerar o zip de novo.
